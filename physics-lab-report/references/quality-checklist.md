# 交付检查

每项以证据判断，不能仅凭源代码存在某个样式就认定最终 PDF 合格。

| 项目 | 通过条件 |
| --- | --- |
| 数据来源 | 实测、引用和模拟有清晰区分，无填造结果，缺失信息明确 |
| 摘要 | 目的和方法简洁，核心结果与结论齐全，无数据堆积、章节索引或心得 |
| 计算 | 原始表和处理方法足以复算，公式量纲正确，无冗长数字运算 |
| 不确定度 | 有适用的计算依据，标准/扩展类型明确，覆盖因子和假设可追溯 |
| 表格 | 最终文档为三线表，无竖线和逐行分隔，单位和表号统一 |
| 公式 | 居中、编号靠右、上下标正确，正文能按号引用 |
| 图 | 量、单位、范围和字号合适，编号图注位于图下且与图同页 |
| 正文 | 摘要、正文、结论两端对齐，行距及标题编号一致 |
| 分页 | 无孤立标题、重复段落、内容溢出或意外空白页 |
| 一致性 | 摘要、表、图、正文和结论中的最终值及单位一致 |
| 提交文件 | 正式件为 PDF，已渲染检查；仅交文字/审稿时标明范围 |

若资料不足或工具不可用，写“待补”或“未验证”并说明原因。修复清单与正式报告分开，避免将审稿说明混入提交正文。
